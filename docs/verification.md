# Verification

Record the toolchain, macOS version, commands, and observed result for each validation run. Keep logs and screenshots local, using synthetic data. Do not publish real state or API responses.

## Automated checks

```sh
./scripts/test.sh
./scripts/accessibility.sh
./scripts/build.sh Debug
./scripts/build.sh Release
./scripts/package.sh
```

The package suite covers classification, paste parsing, persistence and recovery, cache reconciliation, mocked GitHub pagination and partial responses, refresh coordination, and the accessory contract and cancellation. The test script also runs hosted app tests through the Stow scheme with local ad-hoc signing. The app detects the test host before normal startup so these tests cannot load the normal state folder. Builds check compilation of the native app. Packaging verifies the ad-hoc signature and both executable architectures, strips build-machine debug paths before signing, then emits a ZIP checksum. None of these checks establishes a real-account GitHub flow or complete UI acceptance.

`scripts/accessibility.sh` runs Xcode's accessibility audit (`performAccessibilityAudit()`) through the `StowUITests` scheme. It launches the Debug app with `--stow-testing-state <temporary folder> --stow-demo` and audits the board with one pull request and one note open, a detached note, and Settings. The audit checks contrast, element descriptions, hit regions, clipped text, traits, press actions, and parent/child structure. A hosted test can't do this, because SwiftUI builds its accessibility tree only for a connected assistive app. UI automation needs Automation Mode, which macOS may ask an administrator to approve, and the test moves the pointer while it runs. Two elements outside Stow's views are exempt: the virtual Touch Bar that UI testing adds, and a group that macOS 26 nests inside the titlebar zoom button. Contrast is measured from screen pixels. On a 1x display, such as a non-Retina external monitor, small anti-aliased text measures lower and passes or fails with its letters, so contrast issues are logged there without failing; Retina runs enforce them. Run it on a Mac before a release and after UI changes. The audit can't judge reading order, label wording, or keyboard flow, so the manual keyboard and VoiceOver checks still apply.

CI uses Xcode 16.4 on `macos-15`, runs package and hosted Debug app tests, and builds universal Release. The hosted test step already builds Debug, so a duplicate Debug build is omitted. Hosted tests use ad-hoc signing without a development team or signing credential. A Linux job scans history and files with Gitleaks 8.30.1. Native checks run after it only for code, project, dependency, script, or workflow changes, plus explicit manual runs. Push builds cover `main`; feature branches run through their PR, avoiding duplicate push/PR builds. It does not sign for distribution, notarize, authenticate with GitHub as a user, or upload app data. CI doesn't run the accessibility audit; it's a local check before a release. A separate `release` workflow builds the unsigned DMG for each published release and attaches it with its SHA-256 and a build provenance attestation.

## Manual acceptance

- Start with synthetic state. Create, edit, detach, close, reopen, and explicitly delete notes. Verify selection, undo, copy/paste, Markdown styling while typing, Command-click links, a long note growing while you type in it and shrinking after a click elsewhere, the note header's file, export, and delete buttons, and the last edit after quit and restart. Collapse and expand Notes like the other sections, open Settings over a pinned board, pin a card past the first three in a section, and check repository colors and check icons in a light and a dark theme.
- The board's and each detached note's headers share the title bar row with the window buttons. Drag each window by the header's empty space, and double-click there to zoom or minimize as the system's title bar setting says. Click **Start typing a note…** and type: the note stays. Start another and leave it empty, then open a different note or press **+**: the empty one goes away. Pin, add a personal note to, and dismiss a card from its icons.
- Keep multiple detached notes open. Change each note’s always-on-top setting. Hide and reopen the board through the Dock and Command-0. Confirm window restoration on one display and after disconnecting another display.
- Disable GitHub and verify notes-only use. Test missing `gh`, authentication failure, offline refresh, inaccessible pins, rate limits, partial responses, and an account switch. Preserve cached content and keep incomplete readiness conservative.
- With a deliberately authorized test account, verify authored PRs, direct review requests, pin/dismiss/restore, lazy details, and browser links against GitHub. Use synthetic repositories for shareable evidence.
- Enable the sample on the board and one note. Disable each while refreshing. Confirm other content remains usable and unavailable module settings survive restart.
- Edit a managed Markdown file in another editor, including an atomic save; verify source reload, detected conflict copies, clean external deletion, and immediate quit. Export notes and a full backup; restore into disposable state and check the retained old folder, restored windows, pins, and appearance. Reopen external-editor files after restoration.
- In a disposable state directory, test corrupt and unsupported state. Confirm writes stay blocked, explicit recovery creates a backup, and failed recovery preserves the original. Test an unwritable destination without changing normal user storage.
- Check keyboard navigation, VoiceOver labels, text scaling, contrast, a 320-point board width, and a 260-point detached note width.
- Verify appearance changes, theme import/export, opacity, Reduce transparency, and text-editing preservation using the [appearance checklist](appearance.md#manual-checks). Collapse and expand Needs you and Waiting, then relaunch to check persistence. In Settings → Board, reorder sections, change the cards shown before Show more, and allow Notes to collapse; creating a note should expand Notes again. Scroll a long board and confirm section titles stay pinned. Open and close board notes, check one-at-a-time and the start-collapsed setting, and pop a note out from its row.
- Profiles, with synthetic state and at least three profiles. Run each check in one profile and then another, and record what you see.
  - Several profiles on screen: boards and detached notes from different profiles stay separate, each shows its own name, color, and icon, and nothing from one profile appears in another.
  - Create: choose **New profile…** from the File menu, the Dock menu, the board's profile menu, and Settings → Profiles. The sheet asks for a name and a color and shows a message for an empty name or one another profile uses. The new profile opens empty, with GitHub off.
  - Rename, recolor, and choose an icon in Settings → Profiles. A new name saves on Return or when the field loses focus, and window titles and menus follow; an empty or duplicate name shows a message and the field goes back to the saved name. A color from the well tints the board header's profile icon. The icon picker takes a symbol from its grid, any SF Symbol name, a single emoji, or **None**, and refuses an unknown symbol name or more than one emoji. Relaunch and confirm all three stay.
  - Reorder: the up and down buttons move a profile, are disabled at the ends of the list, and appear only with more than one profile. The Dock menu, the Profiles menu, and ⌃⌥1 to ⌃⌥9 follow the new order after a relaunch too.
  - Hide and show: hide a profile and confirm its board and detached notes disappear together without minimizing into the Dock, then show it and confirm the same frames and window levels. Repeat with **Keep always-on-top notes visible when hiding** off and on; with it on, always-on-top notes stay until you minimize or close them. Hidden profiles should not poll GitHub, and showing one refreshes it.
  - Close and reopen: close a profile, check its windows and refreshes stop, reopen it, and confirm its board and detached notes return. Close the last open profile, then click the Dock icon to reopen the most recently active one.
  - Switching by keyboard: ⌃⌥1 to ⌃⌥9 switch to that position, and ⌃⌥] and ⌃⌥[ move to the next and previous profile, wrapping. Check them with the board focused, while a note's text view has focus, and with a non-US keyboard layout. Confirm they work only while Stow is the active app. Repeat with **Hide when switching away** on and off, and with Reduce Motion on. A switch should be immediate.
  - Menus: the Dock menu lists every profile with its state, switches, and offers **New profile…**; with one profile it offers only **New profile…**. The Profiles menu in the menu bar appears once a second profile exists, or with **Always show profile name** on, and lists every profile with Next profile and Previous profile; with one profile and the setting off, it and its shortcuts are gone. The Window menu tells windows apart by profile name. New note, Refresh GitHub, Settings…, and Show board name the profile when more than one exists.
  - Board profile menu: click the profile icon in a board's header. With several profiles it lists the other profiles with their state, then **Hide profile**, **Close profile**, **New profile…**, and **Profile settings…**; with one profile it offers only the last two. Choosing another profile switches to it and hides this one unless **Hide when switching away** is off. Each item acts on that board's profile.
  - VoiceOver: the profile icon button, the profile menu, the owner control, window titles ("Work", a note's title with "— Work", "Work settings"), and the account-mismatch banner read clearly and the color is never the only cue.
  - Window restoration: quit with some profiles visible, some hidden, and one closed, relaunch, and confirm each returns as it was. If none was visible, the most recently active profile shows. Then change which profiles are visible, hidden, and closed, force quit, and relaunch: each profile returns as it was at the last normal quit, not at the force quit, because Stow records the open profiles only while quitting (`recordSession` runs only from `prepareToQuit`).
  - Delete: **Delete…** asks "Delete <name>?" with **Move to Trash** and **Cancel**. Cancel changes nothing; Move to Trash closes the profile and moves its folder to the Trash. With only one profile, Settings shows no **Delete…** button. Deleting a profile another process holds is refused. In Finder, Put Back returns it, and Stow lists it again when it comes forward, with GitHub and accessories off. Close a profile and move its folder to the Trash in Finder. With Stow in the background, choose that profile from the Dock menu: Stow says it can't find it, drops it from its menus, and leaves no folder behind. Bringing Stow forward first reloads the list, so the profile is already gone from the menus and this message doesn't appear. Also delete the first profile and check it moves to `profiles/<id>/` first.
  - Second launch: start Stow, launch a second copy, and confirm it exits at once and brings the running copy forward without changing any profile's `state.json`.
  - Older build: with the first profile in the data folder, open it in an older build while the new build is running and confirm the new build leaves that profile closed with a message; other profiles open normally.
  - Index: corrupt `profiles.json` in a disposable folder and confirm every profile is still found, the index is preserved, and **Reset profile list** moves it to a backup first.
- Owners, with synthetic pull requests from at least three owners: the owner control appears only with more than one owner or an active selection, counts exclude dismissed cards, **Add owner…** works, selection survives restart, and pins stay visible. Confirm warnings, incomplete-data messages, and readiness do not change with the selection. Check **Group by owner**, **Owner order**, **Keep only selected owners on disk** (look at `state.json` and a new backup), and **Hide notes linked to hidden owners**.
- Account mismatch: with a stubbed `gh` answering as a second login, confirm the profile pauses with the banner, keeps its cards marked stale, and fetches no details; **Use X here** clears that profile's cards, details, and dismissals and keeps pins and notes.
- Run on macOS 14 and a current macOS version. A newer build host does not prove minimum-version runtime behavior. Test Intel hardware when available; a universal binary alone does not prove its runtime behavior.
